# Project Context

## Project
- Name: `FilaFacil Acessivel`
- Domain: inclusive queue management for healthcare units
- Stack: Next.js 14 App Router, React 18, TypeScript, Tailwind CSS, Supabase, Recharts, Vitest, GitHub Actions

## Current implemented routes
- `/` redirects anonymous users to `/totem` and authenticated users to the default route for their role
- `/login` public login page
- `/totem` public self-service ticket generation
- `/painel-chamada` authenticated public-call panel
- `/atendente` authenticated attendant screen
- `/medico` authenticated doctor screen
- `/admin` authenticated admin dashboard and user management

## Current product state from repository
- Core queue flow is implemented across totem, attendant, doctor, public panel, and admin dashboard.
- Ticket formatting is done in app code via `formatTicket(prefix, ticketNumber)`.
- Tickets now support `is_priority`, display `P` in the formatted label when applicable, and priority ordering is active in attendant and doctor call-next flows.
- Authentication is implemented with Supabase Auth plus a custom `app_users` role table.
- Admin user bootstrap exists in code:
  - username: `ADM`
  - password: `Filafacil@2026`
- Main navigation exists across internal screens.

## Accessibility state
- Phase 1 completed: high-contrast mode infrastructure exists and is wired globally through `HighContrastProvider`.
- Phase 1 UI emphasis is currently strongest on `/totem`.
- Phase 2 completed: `/painel-chamada` has browser speech synthesis for new calls, plus audio toggle and repeat-last-call control.
- Phase 3 completed: `/totem` has guided voice mode using browser speech synthesis plus speech recognition with fixed commands and confirmation before ticket generation.

## Validation status at time of workflow audit
- Lint passes.
- Test suite passes.
- Build passes.
- Typecheck passes after `.next/types` is regenerated by a build in this local workspace.

## Important repository gaps
- The repository does **not** contain the base Supabase SQL schema for `queues`, `tickets`, `calls`, or the queue RPC functions used by the app.
- The repository only versions `supabase/auth.sql`.
- There is no seed script in `package.json`.
- Any future backend/database work must first account for this missing source-of-truth gap, or explicitly follow the current app-side workarounds now used for priority-aware call ordering.
